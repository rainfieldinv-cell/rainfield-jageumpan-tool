### 2-5. 이자지급일 규칙 편집기 (`data-payrules`)

한 칸 안에 들어가는 것:

* `data-uw-pay-type` : `pre`(선취) / `post`(후취)
* `data-biz-mode` (`data-bizsel` 있는 칸만) : `off`(말일 고정·기본) / `on`(말일 이동) / `none`(조정 안 함)
* 규칙 줄 여러 개 (`[data-rule]`), 각 줄 :
  * `data-rule-months` — N개월 (기본 3)
  * `data-rule-mode` — `untilMaturity`(만기까지 반복·기본) / `count`(지정 횟수)
  * `data-rule-count` — 반복 횟수 (mode=count 일 때만)
  * `data-rule-anchor` — **지급 기준일 1~31**. 비우면 실행일 일자를 따라감

## 3. 계산 규칙

### 3-1. 날짜 유틸 (UTC 고정)

```
parseDate("YYYY-MM-DD")  → Date (UTC 자정)
addMonths(d, n)          → EDATE 와 동일. n개월 뒤 같은 일자,
                            그 달에 없으면 그 달 말일로 보정
anchorTo(d, day)         → 그 달의 day 일. 그 달에 없으면 그 달 말일
daysBetween(a, b)        → (b - a) / 86400000, 반올림
```

### 3-2. 구간 분할 (`buildPeriods`)

규칙 줄을 위에서부터 순서대로 적용. `cursor` 는 실행일에서 시작.

```
기준일(anchorDay) 없음 :  말일 = addMonths(cursor, N)
기준일 있음           :  anchorBase = anchorTo(addMonths(anchorBase, N), anchorDay)
                          말일 = anchorBase
                          (영업일 조정 전 원래 날짜로 이어간다)

mode = count          :  count 회 반복
mode = untilMaturity  :  cursor < 만기 인 동안 반복
말일 > 만기           :  말일 = 만기 로 자름
무한루프 방지          :  guard 600 회
```

### 3-3. 경계 모델 + 주말·공휴일 처리 (`computeEffective` / `applyUwOverrides`)

구간 i 의 **초일 = 경계[i], 말일 = 경계[i+1]** (경계를 공유하므로 구간이 항상 붙어 있다).

| `bizMode` | 말일 경계 | 지급일 |
|---|---|---|
| `on` (말일 이동) | i>0 인 경계를 **익영업일로 밀음** → 일수·이자 늘어남, 다음 초일도 밀림 | 익영업일 |
| `off` (말일 고정) | 그대로 | 익영업일 |
| `none` (조정 안 함) | 그대로 | 그대로 |

> **주의 — 값이 비어 있으면 `off` 다.** "조정 안 함" 은 반드시 `none` 이라고 넣어야 한다.
> ```
> bizModeOf(seg) : seg.bizMode 가 비었으면 "off",  "none" 이면 null(조정 안 함)
> ```
> 사채권자 쪽(`bizModeFor`)은 비었을 때 화면 위 📌 전체 설정(`#cond-bond`, 기본 `off`)을 따른다.

* 사용자가 표에서 직접 고친 날짜(오버라이드)는 **항상 그대로 존중**하고 영업일 재조정하지 않는다.
* 오버라이드는 세그먼트별로 보관 : `uwOverrides.asset / bond0 / bond1 / bond2` 의 `{bd:{}, pay:{}}`

### 3-4. 지급일 · 이자

```
지급일 = 선취 → 초일,  후취 → 말일   (그 뒤 위 표대로 익영업일 조정)
이자계산일수 = 말일 - 초일
이자금액(세전) = floor(원금 × 금리 × 일수 / 365)      ← 원단위 절사
```

### 3-5. 후순위대여 (`wht.js`)

```
대상    : 기초자산(Cash-in)의 이자금액만. 참여수수료는 제외.
원천세  = ROUNDDOWN(이자금액(세전) × 원천세율, -1)   ← 10원 단위 절사
지방세  = ROUNDDOWN(원천세 × 지방세율, -1)           ← 10원 단위 절사
합계    = 원천세 + 지방세
맨 아래 합계행은 각 열 SUM
```

`floor10(x) = sign(x) × floor(|x|/10) × 10`

### 3-6. 추가자산관리수수료 (선택)

```
금액 = 기초자산 이자 − 사모사채 이자들의 합
놓는 위치 = 사모사채 지급일 행
```

**구간 수가 서로 다르면 자동계산을 통째로 건너뛴다**(짝이 안 맞아 틀린 값이 나오므로).
그 경우 전부 빈칸이 되고 직접 입력해야 한다.
손으로 고친 칸은 노란색으로 고정되고, 비우면 다시 자동계산된다.

### 3-7. 자동채움

**기초자산 → 사모사채 1회차** (`ASSET_TO_BOND`)

| 기초자산 | → | 사모사채 |
|---|---|---|
| `loanDate` | → | `issueDate` |
| `loanAmount` | → | `issueAmount` |
| `loanRate` | → | `issueRate` |
| `maturityDate` | → | `maturityDate` |

**1회차 → 2·3회차** : 모든 `[data-field]` `[data-note]` + 인수수수료(모드·요율·금액) + 이자지급일 규칙 전체

**공통 규칙** : 사용자가 직접 고친 칸은 그 칸만 독립(dirty)이 되어 이후 덮어쓰지 않는다.
프로그램이 값을 넣을 때는 `_mirroring` 플래그를 세워 dirty 로 치지 않는다.

**① 입력 → 사채권자 세트** (`app.js syncBondSets`)
사모사채 패널 `data-bond="N"` → 세트 `data-round="N"` 으로 값 복사.
`title → bondName`, 나머지는 같은 이름. 비고·인수수수료·이자지급일 규칙·주말공휴일 처리도 함께.

### 5-1. 셀 지도

## 6. 엑셀 ②  전체(업무수탁) 자금판 (`excel_uw.js`)

* 시트 이름 : **`이자 스케줄`** (한 장)
* 지급날짜 축 기준으로 기초자산·사모사채를 좌우결합

### 6-1. 열 배치 (세그먼트당 7열)

```
A   여백
B   지급날짜
C ~ I    기초자산            (값 열 D)
J ~ P    사모사채 1-1회      (값 열 L,  이자금액 P)
Q ~ W    사모사채 1-2회      (값 열 S,  이자금액 W)
X ~ AD   사모사채 1-3회      (값 열 Z,  이자금액 AD)
다음 한 칸  추가자산관리수수료  (1회 Q · 2회 X · 3회 AE)
```

세그먼트 내부 : `초일 · 말일 · 지급일 · 일수 · 금리 · 수수료 · 이자금액`

열 폭 : 기초자산 `15.5 29.6 16.4 12.9 8.5 15.1 15` · 사모사채 `15.5 15.5 17.8 12.8 9.8 14.2 15`
`A 4.5` `B 15` · 추가수수료 `16`

### 6-2. 상단 정보 블록 (2~9행)

| | 라벨(2칸 병합) | 값 | 비고(2칸 병합) |
|---|---|---|---|
| 기초자산 | B:C | **D** | E:F |
| 사모 1-1회 | J:K | **L** | M:N |
| 사모 1-2회 | Q:R | **S** | T:U |
| 사모 1-3회 | X:Y | **Z** | AA:AB |

행 순서

| 행 | 기초자산 | 사모사채 |
|---|---|---|
| 2 | 제목 + "비고" | 제목 + "비고" |
| 3 | 대출실행일 | 사모사채 발행일 |
| 4 | 차주 | 발행 유형 |
| 5 | **대출금액(원)** | **사모사채 발행금액(원)** |
| 6 | **대출금리** | **사모사채 발행금리** |
| 7 | **참여수수료** | **사모사채 인수수수료(원)** |
| 8 | 이자지급일 ("N개월 선취") | 이자지급일 ("N개월 후취") |
| 9 | 만기일 | 만기일 |

테두리 : 제목행(2행) 위·아래 `medium`, 값칸 오른쪽 `medium`, 비고칸 왼쪽 `medium`,
가운데 줄은 라벨·값 `dashed` / 비고 `dotted`, **마지막 행(9행) 아래는 `medium` 으로 표를 닫는다.**

### 6-3. 스케줄 헤더 · 데이터

```
12행  그룹 헤더   "▶ 기초자산 이자지급 스케줄 (Cash-in)"
                  "▶ 1-1회 사모사채 이자지급 스케줄 (Cash-out)" …
                  (1회일 때는 그냥 "▶ 사모사채 …")
13행  열 헤더     (세그먼트 7열 이름)
11행  마지막 사모사채 이자금액 열 위에 "(단위 : 원)"
14행~ 데이터
합계행 = 마지막 데이터행 + 1
```

**수식**

```
기초자산   (C 초일 · D 말일 · E 지급일 · F 일수 · G 금리 · H 참여수수료 · I 이자금액)
  초일·말일·지급일 = 값 (화면과 같은 실효 날짜)
  F{r} 일수      = D{r}-C{r}
  G{r} 금리      = $D$6
  H{r} 참여수수료 = $D$5*$D$7        ← 첫 구간에만. 요율이 없으면 수식을 쓰지 않음
  I{r} 이자금액   = ROUNDDOWN($D$5*G{r}*F{r}/365,0)
                     예) I14 = ROUNDDOWN($D$5*G14*F14/365,0)

사모사채 1-1회 (J 초일 · K 말일 · L 지급일 · M 일수 · N 금리 · O 인수수수료 · P 이자금액)
  발행일 행(base) : J{r} 초일 = L3
                    O{r} 인수수수료 = 요율모드 $L$7*$L$5 / 금액모드 $L$7
                                 (값이 없으면 수식을 쓰지 않음 — 빈칸 곱하면 #VALUE!)
                    P{r} 이자금액 = 0
  각 구간          : M{r} 일수   = K{r}-J{r}
                    N{r} 금리   = $L$6
                    P{r} 이자금액 = ROUNDDOWN($L$5*N{r}*M{r}/365,0)
                     예) P15 = ROUNDDOWN($L$5*N15*M15/365,0)

  1-2회는 Q~W (값 열 S), 1-3회는 X~AD (값 열 Z) 로 같은 모양이 반복된다.

추가자산관리수수료
  = 기초자산이자셀 − 사모사채이자셀들          ← 구간 수가 같을 때만
  손으로 고친 값이 있으면 그 값을 그대로 넣는다

합계행
  기초자산 : 일수 · 참여수수료 · 이자금액 SUM
  사모사채 : 일수 · 인수수수료 · 이자금액 SUM
  추가수수료 SUM
```

### 6-4. 후순위대여 표

이자 스케줄 **합계행 아래로 3칸 띄우고**(합계행+4) 시작.

```
{top}    "후순위대여"
{top+1}  B 이자지급일 │ C 이자금액(세전) │ D 원천세 │ E 지방세 │ F 합계
{top+2}~ B = 기초자산 지급일셀 참조   C = 기초자산 이자금액셀 참조
         D = ROUNDDOWN(C{r}*14%,-1)
         E = ROUNDDOWN(D{r}*10%,-1)
         F = E{r}+D{r}
마지막   "합 계" + C·D·E 열 SUM
```

## 8. 다시 만들 때 주의할 점

1. **날짜는 전부 UTC 자정 기준**으로 다룬다. 시간대 때문에 하루가 밀리는 사고를 막기 위함.
2. **엑셀에는 값이 아니라 수식을 넣는다.** 열어서 발행금액·날짜를 고치면 이자가 다시 계산돼야 한다.
   단 초일·말일·지급일은 영업일 조정 결과라서 **값**으로 넣는다.
3. **빈칸에 곱하는 수식을 쓰지 않는다.** 참여수수료·인수수수료는 값이 있을 때만 수식을 쓴다
   (`=$D$5*$D$7` 에서 `D7` 이 비면 `#VALUE!`).
4. **이자는 절사(ROUNDDOWN/floor)**, 반올림이 아니다. 후순위대여의 원천세·지방세는 **10원 단위 절사**.
5. **구간 수가 다르면 추가자산관리수수료는 계산하지 않는다.** 억지로 짝지으면 틀린 값이 그럴듯하게 나온다.
6. **자동채움은 칸 단위로 독립**시킨다. 사용자가 고친 칸을 나중에 덮어쓰면 안 된다.
7. 공휴일은 손으로 적지 말고 `holidays` 라이브러리로 뽑는다(현재 2025~2028 수록, 대체공휴일 포함).
8. 특정 딜의 숫자를 코드에 박지 않는다. 전부 입력값에서 온다.
